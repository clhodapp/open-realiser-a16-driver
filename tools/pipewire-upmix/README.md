# Realtime surround upmix for the A16

Run `result/bin/a16-upmix` alongside the `a16-driver --profile custom-2` USB driver.
This publishes three selectable playback devices:

| Device | Intended input | Processing |
|---|---|---|
| Realiser A16 Stereo to 7.1.4 (PSD) | Stereo | PipeWire PSD center/surround upmix, then four height feeds |
| Realiser A16 5.1 to 7.1.4 | 5.1 | Preserve six original channels; derive rear pair and four height feeds |
| Realiser A16 7.1 to 7.1.4 | 7.1 | Preserve eight original channels; derive four height feeds |

Select the appropriate device for the source format in KDE or the player.
Native targets are `a16.upmix.stereo`, `a16.upmix.5.1`, `a16.upmix.7.1`.
These are explicit input formats, not automatic source-format detection. Do not
send 7.1 through the stereo input: that would downmix it before processing.
The stereo path internally feeds the 7.1 height stage.

All three output named FL FR FC LFE SL SR RL RR TFL TFR TRL TRR to
`ozzy.a16.playback`. The configured A16 Custom #2 room maps the height positions
to Lh/Rh/Lhr/Rhr. Inner fronts, rear center and true overhead are not generated
by these presets. Other rooms must provide and correctly map the output positions.
The direct A16 playback device remains available to bypass the upmixer or play
native immersive material. No default device or existing application routing is
changed by the launcher.

## Bass and original channels

Keep the Realiser's bass management at Virtual/120 Hz and the verified LFE gain
setting. Stereo has no synthetic LFE. Existing LFE in 5.1/7.1 passes through at
unity gain with no filtering and is excluded from every derived channel. The
other original 5.1/7.1 channels also pass through unchanged inside these graphs.
The A16 still applies its own rendering and bass management afterward.

## The ambience baseline

This is a configurable matrix/ambience processor using PipeWire builtins, not an
adaptive source separator, Dolby/DTS decoder or reconstruction of height objects.
The stereo PSD stage retains the previously validated settings: normalized
matrix, 12 ms rear delay, 63-tap Hilbert phase shift, 12 kHz center lowpass, no
widening. Its sides contain attenuated front signals; rears use the stereo
difference. It is not a fully ambience-only source separation algorithm.

The added height signals use 0.12 times a channel-pair difference, filtered from
250 Hz to 7 kHz. Front heights derive from FL/FR; rear heights derive from RL/RR
for 7.1 and SL/SR for 5.1. Independent 7/11/19/23 ms delays spread the four feeds.
For 5.1, the additional rear pair uses 0.18 times the side-pair difference,
with 12/17 ms delays. Original center and LFE never feed these added channels.
Correlated mono in the source pairs cancels from the height derivation; hard-panned
material can still produce height output. Audition this before choosing it as a
default for all music. Edit `generate.py`, regenerate, and restart only the upmixer
to tune the amounts, filters or delays.

## Operation and verification

This runs as a standalone PipeWire client. Stop with Ctrl-C; the USB bridge,
current card profile and stereo capture source remain running. There is no
installed autostart service. Run one instance. The output targets only the A16,
with fallback disabled. Restart this client after disconnection if needed.
Requested rate is 48 kHz and latency is 20 ms, in addition to the bridge/device.

All processors operate in float, but summing the additional virtual speakers can
raise the Realiser's binaural peak. These presets do not impose a limiter or
promise matched loudness against bypass. Existing-channel unity gain does not
imply equal final headphone loudness. A16 return capture can be used for measured,
loudness-matched comparisons and prerenders as before.

The JSON-compatible configuration is generated by `generate.py`; `--check`
verifies it during the package build. Live validation captures are kept in
`experiments/upmix-immersive-validation` in the parent workspace. They test each
source channel separately, existing-channel gain/crosstalk, LFE isolation, derived
rear/height activity, and both rear/side conventions for 5.1. Tests temporarily
mute unrelated playback streams and restore them afterward so measurements are
not contaminated.

## Static stereo upmix

`a16-static-dsp PSD.json HEIGHTS.json` processes interleaved stereo float32 on
stdin into 16 interleaved float32 output channels on stdout. It calls the same
PipeWire SPA `audio.convert` PSD implementation and `filter.graph` height stage
synchronously. No PipeWire server connection, soundcard, clock servo or realtime
scheduling is involved. This is stereo-input processing; the live 5.1/7.1 paths
are not exposed by this tool yet.

The output order is the explicit A16 Custom #2 USB slot order:
`FL FR FC LFE FLC FRC SL SR RL RR RC TFL TFR TRL TRR TC`.
LFE and unused Custom #2 positions remain zero; bass management stays on the A16.
Configuration files are extracted from the live JSON config, not independently
reimplemented equations. Feed contiguous samples through one invocation so
filter/delay state persists across track boundaries. A circular album needs
end-of-album pre-roll before its opening and beginning-of-album post-roll after
its ending; trim these at exact sample boundaries after processing.

A 42-minute, 16-channel 24-bit file exceeds ordinary WAV's 4 GB limit. RF64 WAV
is suitable. Because Custom #2's USB order is not canonical WAVE speaker order,
the RF64 uses an unspecified 16-channel layout and needs the explicit map above
when played through PipeWire. Do not let a player guess a surround layout.
The static file contains multichannel PCM, not a binaural render.

Use `result/bin/a16-play-static FILE.rf64.wav` for these Custom #2 files. It checks
the active card profile, applies the explicit channel map, and feeds the hardware
sink directly with upmixing disabled. It does not change device/room settings or
start a capture. Leave the static file's -12 dB rendering headroom intact.
